## 1. 目标与范围

用户要求设计并发版 S7 AI Studio，参考 Modbus AI Studio 的架构，支持西门子的所有系列。

本草案将“所有系列”解释为西门子 PLC 产品家族：S7-200 / 200 CN、S7-200 SMART / SMART G2、S7-300、S7-400、S7-1200 / 1200 G2、S7-1500、带 CPU 的 ET 200、相应软件与集成控制器，并纳入 LOGO! 和 SIMATIC S5 的兼容路线。各家族的紧凑型、工艺型、故障安全型及冗余型按具体 CPU、固件和通信接口验证。

用途沿用参考项目的现场调试与诊断：连接设备、按点表读取、解释值与报文、验证写入、记录历史、提供 AI 诊断。验收以可追溯的连接和读写结果为准。

以下是本草案的假设，可在评审时修改：

- 老设备接受使用已验证的通信模块或以太网网关；原生 PPI 与厂商编程适配器单独开发和验收。
- 保留 Windows / macOS 桌面端、CLI、模拟器和 Linux Web 端的产品形态。
- SINAMICS 驱动器参数和 SINUMERIK 数控功能需要独立驱动与需求设计；本草案只覆盖其中经 PLC 接口开放的数据。
- “全系列”是兼容范围，不意味着所有年代、所有固件、所有电缆均可直接连接。没有公开可用读写接口的设备应明确说明接入条件；未验证的组合不得宣称已经支持。

## 3. 兼容矩阵

下面是目标接入路线，不是已通过实机测试的支持清单。

| 产品家族 | 目标接入方式 | 地址与配置差异 | 发布验收重点 |
| --- | --- | --- | --- |
| S7-200 / 200 CN | CP 243-1 等已验证的 Ethernet 路径；PPI 驱动或已验证网关 | V / M / I / Q 等区域；V 区与后端数据区的映射由设备配置档案处理 | CPU、模块、连接资源和映射分别验证 |
| S7-200 SMART / SMART G2 | 具备 Ethernet 接口和相应服务的 CPU 使用 S7 over TCP；其他型号按实际接口接入 | V 区、TSAP、各代 CPU 的权限与请求上限分别配置 | 固件和 PUT/GET 服务器开关；不能把一代默认值套给所有型号 |
| S7-300 / C7 对应 CPU | CPU PN 接口、支持 S7 服务的 CP，或已验证 MPI / PROFIBUS 网关 | Rack / Slot、Local / Remote TSAP、DB / M / I / Q，支持时开放 T / C | PN、CP 和网关连接分别记录兼容结果 |
| S7-400 / H / FH | PN / CP 或已验证网关 | 机架槽位、连接资源、各 CPU 的访问能力 | 单 CPU 访问与冗余切换分开验收；切换期间写入结果不能假定成功 |
| S7-1200 / 1200 G2 | 允许时使用经典 S7 绝对地址读写；配置可用时使用 OPC UA | PUT/GET 权限、标准 DB；符号变量走具备该能力的驱动 | 原代与 G2 分开；按固件验证权限和节点暴露条件 |
| S7-1500 / C / T / F / TF / R / H | 经典 S7 绝对地址路径；OPC UA 符号路径 | 标准 DB 与优化 DB 分开；安全通信、证书与用户权限按后端处理 | 不将经典 S7 TCP 实现标成 S7CommPlus；冗余和工艺能力单独标注 |
| ET 200S / X / pro / SP 等带 CPU 产品 | 根据实际 CPU 与接口复用相应驱动或网关 | 产品名称不决定能力，CPU 订货号和固件决定配置 | 不把普通远程 I/O 站当作独立 PLC；不同代 CPU 分开测试 |
| WinAC / Software Controller / Open Controller / SIPLUS / Drive Controller PLC 部分 | 根据运行时实际暴露的 S7 / OPC UA 接口接入 | 网络或本机接口、运行时版本与权限 | TCP 可访问性和具体运行时单独验证 |
| LOGO! 0BA7 / 0BA8 及后续兼容型号 | 型号支持的 Ethernet S7 连接 | 显式 TSAP 和 VM 映射，不套用 S7-300 默认参数 | LOGO!Soft Comfort 连接配置与各代映射分别验证 |
| 更早 LOGO! | 只接入确有受支持通信接口或官方/厂商映射方案的具体型号 | 不具备通用 Ethernet S7 能力时明确显示限制 | 没有可用数据接口时标记无法通过当前方式接入 |
| SIMATIC S5 | 已验证的专用网关；后续按设备支持的 AS511、3964R / RK512 或 CP 协议增加独立驱动 | TTY 电气接口、DB 字寻址、协议格式与 S7 不同 | 指定 CPU、接口、适配器和映射，独立验收，不假定 TCP 102 通用 |

F 型 CPU 在其权限允许范围内读取和写入普通开放变量；本工具不提供 F 程序下载、F 参数更改或安全签名操作。R / H 系列首先验证指定端点的普通访问，系统端点和无缝冗余切换需额外验证后才能发布相应声明。

## 4. 架构选择

| 方案 | 优点 | 代价与适用性 |
| --- | --- | --- |
| **统一业务层 + 分协议驱动，推荐** | 桌面、CLI 和 Web 共用点表、调度、记录、诊断；能逐步纳入老设备和符号访问 | 需要先定义能力、地址和事件模型；最符合全系列目标 |
| 将现有 Modbus 客户端直接替换成单一 S7 TCP 客户端 | 最快得到 Ethernet 演示 | 无法覆盖 PPI、S5 与优化 DB 符号访问；不满足长期范围 |
| 全部经外部 OPC 服务器接入 | 借助外部厂商驱动兼容多类设备 | 安装、许可与网关依赖较多，无法沿用单程序直接调试体验 |

推荐方案保留参考项目的目录分工，并把原来散落在 UI 和 Web 中的设备操作提取到服务层。首个开发子项目是统一模型、经典 S7 TCP 引擎及可运行的 CLI / 模拟器；后续界面和其他驱动各自建立实施计划，避免一个步骤承担全部协议开发。

| 模块 | 职责与边界 |
| --- | --- |
| `internal/device` | ConnectionConfig、TargetAddress、Value、Capabilities、通信事件和驱动接口；不依赖 UI 或具体协议 |
| `internal/profile` | 产品家族配置档案；允许用户覆盖 TSAP、Rack / Slot、区域映射和接口参数 |
| `internal/s7` | TPKT / COTP、S7 握手、协商 PDU、绝对地址读写、逐项结果与报文解码 |
| `internal/ppi` | PPI 编解码与总线会话，独立于 TCP 引擎；按支持的物理适配器验证 |
| `internal/opcua` | 节点浏览、符号值读写、订阅、证书和用户认证；只暴露服务器授权的节点 |
| `internal/gateway` | 已验证网关的连接和映射配置；透传 S7 网关可委托 `internal/s7`，专用协议独立适配 |
| `internal/s5` | 后续 S5 专用驱动；具体协议和硬件路线确认后拆分实现 |
| `internal/transport` | TCP、串口等底层 I/O；厂商编程电缆不能仅凭 COM 端口名称视为受支持 |
| `internal/service` | 连接生命周期、轮询与批读、点表、暂停恢复、工作区快照、写后回读、事件分发 |
| `internal/detect` | 将协议错误与设备配置档案转换为有证据的原因和检查步骤 |
| `internal/simulator` | 覆盖已实现协议的测试服务与故障注入；不将合成档案视作对应系列的实机验证 |
| `internal/recorder` / `ai` / `update` | SQLite 记录、AI 解释和应用更新；通过统一数据模型接入 |
| `internal/ui` / `web` | Fyne 与浏览器交互，调用同一服务 API，不各自实现设备读写 |
| `cmd/s7-ai` / `s7-cli` / `s7-sim` / `s7-web` | 四种程序入口，沿用参考项目形态 |

首版默认内置驱动，接口用于内部模块解耦；不引入动态插件加载、依赖注入框架或用户可编程驱动系统。

## 5. 统一设备与地址模型

ConnectionConfig 按连接方式使用有类型的字段：TCP 地址、TSAP / Rack / Slot；PPI 站址与串口；OPC UA Endpoint、认证与证书；网关型号、下游站址和映射。系列选择仅提供默认配置，连接成功后再结合实际协商与识别结果确认能力。设备不提供身份信息时保留“未知”，不能根据端口 102 推断具体 CPU。

Capabilities 至少包含：驱动类型、绝对/符号地址能力、可读/可写区域、支持的数据类型、最大请求与响应限制、原生位写、订阅、身份查询、实测或配置来源。能力可以是允许、拒绝或未知；连接成功不意味着所有区域均可读写。

TargetAddress 使用以下互斥形式：

- 绝对地址：Area、DBNumber、ByteOffset、BitOffset、Type、ElementCount，例如 `DB1.DBX0.0`、`DB1.DBD4`、`MW10`、`I0.0`。
- 系列专有地址：例如 S7-200 的 `VB100` / `VW100`，由配置档案转换为后端地址，保留用户输入和转换结果以便诊断。
- 符号地址：OPC UA 使用带 Namespace URI 的节点标识，连接后解析 Namespace Index；不能把符号名伪造成 DB 偏移。
- S5 地址：单独保留 DB 与字偏移，再由对应驱动处理。

Value 区分布尔、精确整数、浮点数、字节、字符串和时间类型，保留类型与原始数据。64 位整数在 Web API 中使用带类型的十进制字符串，避免 JavaScript 数值精度丢失。各系列原生类型由能力限制，点表允许额外的数据解释方式。

CSV / XLSX 点表字段包括名称、地址、类型、数量/字符串长度、单位、倍率、偏移、周期、访问模式和可选说明。导入时校验地址宽度、区域、边界和驱动能力；错误行保留行号及原因。S7 原生数值按对应类型规范解码，字节序覆盖仅作为显式的诊断选项。

## 6. 通信与服务行为

经典 S7 TCP 连接按 TCP → TPKT / COTP → S7 参数协商 → 能力与身份查询 → 轮询的顺序建立。默认 TCP 端口 102，但允许覆盖；请求大小根据实际协商、PDU 开销、区域及单项宽度计算。不能只用固定寄存器数量切分请求。

同一会话默认只允许一个未完成请求。不同设备可并发；同一串口总线的设备按适配器和协议限制共享调度。桌面多个读取窗口共用会话调度器，Web 多浏览器共用服务端会话，避免重复连接和重复轮询。

读取结果按点返回质量、时间戳及错误，单项失败不能被整包成功掩盖。批读不跨区域或 DB 合并，不能丢弃完整值的边界。大型值按驱动能力拆分，并明确分段读取不是 PLC 数据的原子快照。

响应通过连接代次、请求引用、消息类型、长度及逐项传输结果匹配。取消或超时后，驱动采用明确的会话恢复策略；不能把旧响应套用到后续请求。读取可有限重试，写入发送后结果不明时标记“执行结果未知”，不自动重发。

写操作由服务端的只读与能力检查统一拦截，桌面、CLI、Web 路径一致。写入后按计划多次读取，区分生效、读回不符、被程序改回和无法确认。优先使用驱动原生位写；不默认以整字节读改写替代，避免覆盖同字节的其他位。跨 PDU 写入若不具备原子保证，界面提前显示分段行为和逐段结果。

诊断先解释连接、TSAP、访问权限、DB 是否开放、地址/长度和协商限制等证据，再提出检查建议。程序不自动修改 PLC 权限、DB 属性或运行状态。AI 接收冻结证据，并沿用参考项目的预览、取消和证据引用；AI 输出不直接执行设备操作。

## 7. 桌面与 Web 交互

桌面沿用 Modbus AI Studio 的多工作区、多读取窗口、报文与日志、解析、点表导入、历史查看和 AI 助手布局。

- 连接栏选择系列与接入方式，普通项显示 IP、端口或串口；TSAP、Rack / Slot 等放入高级配置。
- 每个读取窗口按地址区或点表定义，显示名称、S7 地址、类型、原始值、工程值、质量和更新时间。
- 根据能力显示可用区域与操作；失败时显示具体原因和需要检查的 PLC 配置。
- 报文按所选驱动解析。只有应用层事件时显示事件，不伪造底层原始帧。
- 工作区文件带格式版本，保存连接和点表定义；凭据不写入普通工作区文件。

Web 前端使用服务层 API 和 SSE 分发状态，沿用参考项目的口令、Origin 校验和静态资源嵌入。原生 PPI / 厂商电缆只在运行服务的机器具备相应硬件与驱动时可用，浏览器页面不能替代物理适配器。

## 8. 记录与兼容

统一事件包含 Protocol、Family、ConnectionID、RequestID、Direction、Operation、Targets、Time、RTT、Status、逐项结果和可选 Raw。凭据与证书私钥不进入报文、日志或 AI 证据。

SQLite 保留参考项目的会话、报文和事件结构以及压缩、索引、轮转能力。通过带版本的迁移增加协议元数据和结构化地址；保留旧字段和未知协议值，读取旧 Modbus 数据时仍按其真实协议显示。新 S7 数据不写成虚构的 Modbus 站号或功能码。

历史文件只读打开，迁移只针对本应用管理的可写数据库。升级验证包括旧文件查询、原始字节一致性、压缩数据恢复和新地址字段往返。日志队列满或磁盘写入失败时显示丢弃计数，不阻塞设备通信。

## 9. 开发顺序与验证

| 阶段 | 可独立评审的交付 | 完成标准 |

阶段 C 包含多个独立协议子项目，逐个设计和实现。预览包可以早于全部路线完成；若正式版本使用“全系列支持”的宣传表述，必须注明实际覆盖的接口、型号和固件以及必要的网关条件。不能以配置下拉框覆盖全部家族来替代实机验证。

测试覆盖：

1. 地址与值：位地址、边界、V/VM 映射、字符串长度、精确整数、符号节点和无效类型。
2. 协议：握手失败、协商上限、分帧/粘包、异常长度、分段、逐项错误、响应错配与迟到响应。
3. 服务：多个读取窗口调度、取消、重连、只读拦截、写入结果未知、分段写入和退出清理。
4. 数据：SQLite 迁移、只读历史、压缩/轮转、磁盘错误、工作区版本兼容。
5. 应用：界面软件渲染与原生启动、Web 登录与重连、AI 本地合成测试、更新资产匹配。
6. 实机矩阵：逐个记录 CPU 订货号、固件、CP/网关/电缆及版本、连接参数、只读读取、显式允许的写后回读和异常结果。使用测试专用变量验证写入。

模拟器验证协议实现，不能独自证明全系列兼容。尚未获得某台设备时，其状态保持未验证，并作为发布范围的明确限制。

## 10. 发版设计

版本默认建议从 `0.1.0` 预览开始，具体版本在实施与验收后确定。版本号沿用参考项目的单一来源 `cmd/s7-ai/main.go`；所有入口、打包和更新读取同一版本，测试与打包必须绑定相同提交。

目标安装包：

| 名称模式 | 形态 |
| --- | --- |
| `S7AIStudio-<版本>-Windows-x64.zip` | 静态链接运行库的绿色桌面版 |
| `S7AIStudio-<版本>-macOS-Intel.dmg` | Intel 桌面版 |
| `S7AIStudio-<版本>-macOS-AppleSilicon.dmg` | Apple Silicon 桌面版 |
| `S7AIStudio-Web-<版本>-Linux-x64.tar.gz` | 纯 Go Linux Web 版 |
| `S7AIStudio-Web-<版本>-Linux-arm64.tar.gz` | 纯 Go Linux Web 版 |

Linux Web 的核心与内置驱动必须可以在 `CGO_ENABLED=0` 下构建。依赖平台 SDK 或本地驱动的适配器通过平台能力声明，不因桌面端存在该功能就认为所有安装包都具备。

沿用 `build/release prepare|publish|verify|clean`，实现时补齐：

1. `prepare`：验证仓库、提交、版本和 CI；测试完成后打包，核验文件结构、二进制架构、图标/清单、说明编码及 SHA-256，生成具体支持矩阵与发布说明。
2. `publish`：检查已有 tag 和发布资产；仅发布与已验证提交及校验值一致的内容；GitHub/Gitee 不一致或网络失败时保留可重跑状态。
3. `verify`：重新下载远程资产，检查完整文件 SHA-256、说明与版本；验证桌面更新选包，Web 包不作为桌面更新候选。
4. `clean`：只在两侧发布核验成功后清理本项目 `dist` 下确定属于旧版本的输出。

发布说明必须包含：具体新增功能、型号/固件/接入路径的验证结果、尚未实现与尚未验证的路线、PLC 配置前提、升级和历史数据兼容说明、每个安装包的 SHA-256。直接读写驱动的工程许可和引用代码的许可证在选型时核验，保留参考项目 MIT 版权声明。

当前目录没有 Git 历史和可运行入口，本次工作只产出设计草案。代码开发、依赖选型、测试构建、建立发布仓库与远程发版应在设计范围确认后进行；不能报告已有安装包或发布成功。
