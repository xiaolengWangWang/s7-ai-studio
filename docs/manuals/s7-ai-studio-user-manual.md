# S7 AI Studio 操作手册

> **版本:** v1.1

## 1 整体流程

本手册以 S7 AI Studio `0.5.1` Windows x64 GUI 预览版为操作基准。工具通过经典 S7 TCP（ISO-on-TCP / RFC 1006）读取、写入西门子 PLC 的绝对地址，可用于现场连接验证、viSCADA 物模型属性核对及通信报文取证。

首次使用先完成本机演示，再连接现场 PLC。现场调试从一个已知地址开始，确认地址和数据类型正确后再导入整张点表。需要修改 PLC 数据时，单独执行写入确认和读回核实。

```mermaid
graph LR
    A[下载与启动] --> B[本机演示]
    B --> C[核对 PLC 接入条件]
    C --> D[连接现场 PLC]
    D --> E[读取已知地址]
    E --> F[导入点表与逐点核对]
    F --> G[按需写入与读回]
    G --> H[保存结果与报文]
    H --> I[停止轮询与退出]
```

## 2 启动与认识界面

### 2.1 启动程序

1. **进入**本手册最后的 [第 15 章：下载、源码与校验](#15%20%E4%B8%8B%E8%BD%BD%E3%80%81%E6%BA%90%E7%A0%81%E4%B8%8E%E6%A0%A1%E9%AA%8C)，获取 `0.5.1` Windows x64 GUI 绿色包。
2. **确认**本地已取得 `S7AIStudio-0.5.1-Windows-x64.zip`，并完成文件完整性核对。
3. **解压**整个压缩包到有读写权限的本地目录，例如 `D:\Tools\S7AIStudio`。
4. **双击**解压目录中的 `S7AIStudio.exe`。
5. **核对**窗口顶部版本为 `0.5.1`，初始连接状态为 **「未连接」**。
6. **打开** **「帮助」** 页签，确认能够查看连接和点表格式说明。

运行 GUI 需要 Windows x64 和支持 OpenGL 的图形驱动。使用已发布的绿色包无需安装 Go 或 MinGW。程序首次启动不会自动连接现场 PLC，也不会自动执行写入。

### 2.2 识别工作区

7. **查看**顶部连接区，定位目标地址输入框、**「系列」**、**「连接」**、**「断开」**、**「启动本机演示」** 和 **「停止演示」**。
8. **展开** **「高级连接配置（系列档案未经实机认证）」**，定位 Rack、Slot、TSAP、超时及 V 地址映射参数。
9. **查看**读取操作区，定位 **「地址」**、**「类型」**、**「数量」**、**「读取一次」**、**「开始轮询」** 和 **「间隔（ms）」**。
10. **查看**结果表，定位每个地址的读数、核对结论、质量、时间和错误信息。
11. **查看**写入操作区，定位 **「允许写入（操作前仍需确认）」**、**「写入值」** 和 **「确认写入…」**。
12. **切换** **「报文」**、**「日志」** 和 **「帮助」** 页签，确认能够进入诊断与说明区域。
13. **查看**窗口底部的记录目录和记录状态，确认没有记录失败提示。

| 显示位置 | 含义 | 现场使用方法 |
| --- | --- | --- |
| 顶部连接状态 | 绿色表示已连接，橙色表示连接中，红色表示通信失败 | 先看文字状态，再查看错误详情 |
| 后台操作进度 | 表示连接、读取等操作正在进行 | 等待操作结束，避免连续重复点击 |
| 结果表 **「质量」** | 表示该地址本次读取是否取得有效数据 | 与 **「核对」** 列分别检查 |
| 底部记录状态 | 表示本地记录器是否正常保存通信事件 | 出现记录失败时立即留存界面日志 |

工具会在连接或读取成功后记住连接和点位输入；写入值及 **「允许写入（操作前仍需确认）」** 的勾选状态不会持久保存。本机演示使用临时端口，下次启动不应把上次演示端口当作固定目标。

## 3 使用本机演示完成首次读写

本机演示由程序启动一个回环地址上的合成 S7 TCP 对端，不需要外接 PLC。该对端用于练习工具操作，不模拟真实 CPU 程序、扫描周期或现场设备动作。

1. **点击** **「启动本机演示」**。
2. **等待**顶部状态变为 **「已连接」**，目标显示为 `127.0.0.1` 的临时端口。
3. **查看**结果表中的 `DB1.DBD0`，确认类型为 `DINT`、初始值为 `42`、质量为 `GOOD`。
4. **勾选** **「允许写入（操作前仍需确认）」**。
5. **填写** **「写入值」** 为 `123`。
6. **点击** **「确认写入…」**。
7. **核对** **「确认 PLC 写入」** 弹窗中的目标为当前本机演示地址，地址为 `DB1.DBD0`，类型为 `DINT`，数量为 `1`，值为 `123`。
8. **点击**弹窗中的 **「确认写入」**。
9. **查看**写入结果，确认状态为 `CONFIRMED`，独立读回结论为 **「一致」**。
10. **点击** **「读取一次」**，确认结果值仍为 `123`。
11. **取消勾选** **「允许写入（操作前仍需确认）」**。
12. **切换** **「报文」** 页签，确认能够看到握手、读取和写入对应的收发记录。
13. **点击** **「停止演示」**，确认演示连接结束。

本机演示成功说明程序、基本协议处理和本地读写流程可以运行。现场 PLC 的通信许可、型号兼容性及工程地址仍需单独验证。

## 4 连接现场 PLC 前核对接入条件

### 4.1 准备现场信息

1. **取得** PLC 或通信模块的实际 IP、端口、CPU 型号、固件版本及接入方式。
2. **取得** Rack、Slot 或 Remote TSAP 的工程配置值。
3. **取得**至少一个已知地址的 DB 编号、字节偏移、数据类型及当前预期值。
4. **确认**目标设备或网关提供经典 S7 TCP 服务。
5. **确认**调试电脑能够到达目标网络，目标端口由现场网络策略允许访问。
6. **记录**现场参数来源，确保连接参数与当前在线工程一致。

经典 S7 TCP 常见端口为 `102`。端口可以由网关映射为其他值，应填写实际可达的端口。设备具有网口、能 Ping 通或能被其他工程软件发现，都不能单独证明经典 S7 TCP 可用。

### 4.2 核对系列与连接前提

| 系列选项 | 本工具的连接配置起点 | 需要现场确认的内容 |
| --- | --- | --- |
| `s7-300` | 自动 Rack 为 `0`，Slot 为 `2` | CPU 网口、CP 或网关是否提供对应 S7 服务；实际槽位是否一致 |
| `s7-1200`、`s7-1200-g2`、`s7-1500` | 自动 Rack 为 `0`，Slot 为 `1` | 经典 S7 服务、访问许可、PUT/GET 与目标 DB 的标准访问设置 |
| `et-200sp`、`et-200pro`、`software-controller`、`open-controller`、`drive-controller` | 自动 Rack 为 `0`，Slot 为 `1` | 对应设备是否带 CPU、是否提供经典 S7 TCP 及真实连接参数 |
| `s7-200`、`s7-200-cn`、`s7-200-smart`、`s7-200-smart-g2` | 必须显式填写 Remote TSAP | CPU、通信模块或网关的 S7 TCP 服务；V 地址使用时的映射关系 |
| `s7-400`、`et-200s`、`et-200x`、`winac`、`siplus`、`logo` | 必须显式填写 Remote TSAP | 现场通信模块、连接资源及配置的 TSAP |
| `generic-s7-tcp` | 必须显式填写 Remote TSAP | 其他设备确实提供经典 S7 TCP，且已取得对应连接参数 |

**「系列」** 用于选择参数档案，不会自动识别真实 CPU。上表说明软件如何配置，不能作为全部型号、固件或通信模块均已通过实机认证的依据。

### 4.3 核对 S7-1200/1500 的绝对地址访问

以下工作由维护 PLC 工程的人员执行。不同 TIA Portal 版本和 CPU 固件的界面名称可能不同，以实际工程和对应西门子手册为准。

7. **打开**对应 CPU 的在线或离线工程，核对其 IP 和目标 CPU 身份。
8. **检查** CPU 的保护与访问配置，确认允许当前接入方式读取所需数据。
9. **检查**远端 PUT/GET 通信许可，确认工程允许远端伙伴执行对应访问。
10. **检查**待读取 DB 的块属性，确认目标 DB 使用标准访问，即关闭优化块访问。
11. **核对**目标变量的实际字节偏移和数据类型。
12. **确认**所需工程配置已在在线 CPU 生效，再交由本工具验证已知地址。

西门子官方资料说明了 PUT/GET 访问许可及优化 DB 的访问限制，可参阅 [S7-1200：GET 与 PUT 通信](https://docs.tia.siemens.cloud/r/simatic_s7_1200_manual_collection_enus_20/communication/s7-communication/get-and-put-read-and-write-from-a-remote-cpu)。

> ⚠️ 调整 DB 的优化访问属性或下载 PLC 工程可能影响现有程序和地址布局。应由 PLC 工程维护人员核对影响后实施，不要为了通信测试直接修改生产工程。

## 5 配置参数并连接现场 PLC

### 5.1 填写连接参数

1. **点击** **「停止演示」**，结束已有本机演示。
2. **填写**目标地址为现场的 `host:port`，例如 `192.168.0.10:102`。
3. **选择** **「系列」** 为现场对应选项。
4. **展开** **「高级连接配置（系列档案未经实机认证）」**。
5. **按下表填写**高级参数。

| 字段 | 是否必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| **「Rack / Slot」** | 是 | `-1` / `-1` | `-1` 表示分别使用系列档案默认值；显式值范围为 Rack `0～7`、Slot `0～31` |
| **「Local / Remote TSAP」** 中的 Local | 否 | `0x0100` | 留空使用本地默认值；十六进制值使用 `0x` 前缀 |
| **「Local / Remote TSAP」** 中的 Remote | 否 | `0x0200` | 示例仅展示格式；[第 4.2 节](#4.2%20%E6%A0%B8%E5%AF%B9%E7%B3%BB%E5%88%97%E4%B8%8E%E8%BF%9E%E6%8E%A5%E5%89%8D%E6%8F%90)列出的需要 TSAP 的系列必须填写现场值 |
| **「超时（ms）」** | 是 | `2000` | GUI 默认 `2000` 毫秒，必须大于 `0` 且不超过 `300000` 毫秒 |
| **「V 映射 DB / 偏移」** 中的 DB | 是 | `0` | 默认 `0` 表示未配置映射；使用 V 地址时填写现场指定 DB，范围 `1～65535` |
| **「V 映射 DB / 偏移」** 中的偏移 | 是 | `0` | 默认 `0`；V 地址映射时作为起始字节偏移叠加到地址偏移 |

6. **点击** **「连接」**，或在目标地址框按回车。
7. **等待**顶部状态变为绿色 **「已连接」**。
8. **填写**一个已知地址并按[第 6 章](#6%20%E6%89%8B%E5%8A%A8%E8%AF%BB%E5%8F%96%E5%9C%B0%E5%9D%80%E4%B8%8E%E7%90%86%E8%A7%A3%E7%BB%93%E6%9E%9C)读取，确认取得符合工程含义的值。

填写显式 Remote TSAP 时，工具使用该值建立远端连接，不再根据 Rack/Slot 推导远端 TSAP。`0x0200` 不能作为所有 SMART 或其他 CPU 的通用参数。

### 5.2 配置 V/VM 地址映射

本节适用于使用 V/VM 地址的 `s7-200`、`s7-200-cn`、`s7-200-smart`、`s7-200-smart-g2` 或 `logo` 档案。

9. **取得**设备或网关给出的 V/VM 到 DB 映射关系。
10. **填写** **「V 映射 DB / 偏移」**，例如现场明确规定 V 区映射到 DB1 且基址为 `0` 时，填写 `1` / `0`。
11. **连接**目标设备。
12. **填写** **「地址」** 为 `VD0`，选择与工程一致的 `DINT` 或 `REAL`，数量填 `1`。
13. **点击** **「读取一次」**，确认读数与现场提供的 V 区值一致。

在上述映射示例中，`VD0` 对应 DB1 第 `0` 字节开始的四字节数据；映射偏移若为 `100`，则对应 DB1 第 `100` 字节。未取得映射依据时，不能假定所有设备的 V 区都对应 DB1。

## 6 手动读取地址与理解结果

### 6.1 读取一个原生绝对地址

1. **确认**顶部为 **「已连接」**。
2. **填写** **「地址」** 为已知地址，例如 `DB1.DBD0`。
3. **选择** **「类型」** 为 PLC 工程中的实际类型，例如 `REAL`。
4. **填写** **「数量」** 为 `1`。
5. **点击** **「读取一次」**，或在地址框按回车。
6. **查看**结果表，确认该行 **「质量」** 为 `GOOD`，**「错误」** 为空，**「值」** 与已知工程值一致。

`DB1.DBD0` 只表达 DB1 第 `0` 字节开始的四字节地址，其内容可以按 `DINT`、`DWORD` 或 `REAL` 解码。即使读取成功，类型选错仍可能得到错误的业务数值。

| 地址示例 | 类型示例 | 说明 |
| --- | --- | --- |
| `DB1.DBX52.0` | `BOOL` | DB1 第 `52` 字节第 `0` 位；位号范围 `0～7` |
| `DB1.DBB0` | `BYTE` | DB1 第 `0` 字节 |
| `DB1.DBW4` | `INT` / `WORD` | DB1 第 `4` 字节开始的两字节数据 |
| `DB1.DBD8` | `DINT` / `DWORD` / `REAL` | DB1 第 `8` 字节开始的四字节数据 |
| `DB1.DBL16` | `LINT` / `LWORD` / `LREAL` | DB1 第 `16` 字节开始的八字节数据；需目标工程具备对应类型 |
| `M0.7` | `BOOL` | 标志区第 `0` 字节第 `7` 位 |
| `IW10` | `INT` / `WORD` | 输入区第 `10` 字节开始的两字节数据 |
| `QB2` | `BYTE` | 输出区第 `2` 字节 |

### 6.2 使用 viSCADA 属性标识读取

viSCADA 的 S7 属性标识采用带类型的地址写法。工具根据标识中的类型前缀确定解码方式，可在同一次读取中混用 REAL、BOOL 等类型。

7. **填写** **「地址」** 为 `DB1.R0,DB1.X52.0`，分隔符使用英文逗号。
8. **填写** **「数量」** 为 `1`。
9. **点击** **「读取一次」**。
10. **查看**结果表，确认 `DB1.R0` 按 `REAL` 读取，`DB1.X52.0` 按 `BOOL` 读取。

| 属性标识示例 | 隐含类型 | 说明 |
| --- | --- | --- |
| `DB1.X52.0` | `BOOL` | 第 `52` 字节第 `0` 位 |
| `DB1.B0` | `BYTE` | 单字节无符号值 |
| `DB1.C0` | `CHAR` | 单字节字符，扩展字符按 Windows-1252 处理 |
| `DB1.W2` / `DB1.I2` | `WORD` / `INT` | 两字节无符号 / 有符号整数 |
| `DB1.DW4` / `DB1.DI4` | `DWORD` / `DINT` | 四字节无符号 / 有符号整数 |
| `DB1.R8` | `REAL` | 四字节浮点数 |
| `DB1.LI16` / `DB1.LR24` | `LINT` / `LREAL` | 八字节有符号整数 / 浮点数 |
| `DB1.S32.20` | `STRING[20]` | 字符串从第 `32` 字节开始，最大字符数据长度 `20` 字节，另占两个头字节 |
| `PE0.X0.1` | `BOOL` | 输入区 I 第 `0` 字节第 `1` 位 |
| `PA0.B2` | `BYTE` | 输出区 Q 第 `2` 字节 |
| `MK0.R4` | `REAL` | 标志区 M 第 `4` 字节开始的 REAL |

属性标识的偏移单位是字节。REAL 每项占 `4` 字节，连续 REAL 通常使用 `R0`、`R4`、`R8` 等偏移，实际排列仍以 PLC 工程为准。`PE`、`PA`、`MK` 别名的区域编号必须为 `0`。

本版不解析 Telegraf 的 `DT` 日期时间类型，也不解析计数器 `C` 区和定时器 `T` 区。`DB1.C0` 中的 `C` 是 CHAR 类型前缀，与计数器区域 `C0.*` 含义不同。CHAR 和 STRING 使用 Windows-1252，不支持把中文当作单字节字符写入；其他字符代码页需结合原始字节核对。

### 6.3 读取多个地址或连续数组

11. **填写**多个同类型原生地址，例如 `DB1.DBD0,DB1.DBD8`。
12. **选择** **「类型」** 为这些地址共同使用的实际类型，数量填 `1`。
13. **点击** **「读取一次」**，确认每个地址分别产生一行结果。
14. **填写**一个连续数组的起始地址，例如 `MW10`。
15. **选择** **「类型」** 为 `INT`，数量填 `3`。
16. **点击** **「读取一次」**，确认结果包含从第 `10` 字节开始的三个 INT 元素，即对应 `MW10`、`MW12`、`MW14`。

**「数量」** 表示从每个起始地址读取的元素数，不是地址框中的地址个数。BOOL 和 STRING 要求数量为 `1`；读取多个 BOOL 时，应填写多个独立位地址。单次手动原生地址读取使用统一的类型和数量；混合类型优先使用带类型的 viSCADA 标识或点表。

跨多个协议数据单元（PDU）的读取会分批完成，各批次时间不同，不能视为同一时刻的原子快照。

### 6.4 检查结果表

17. **检查**每行的 **「质量」** 和 **「错误」**，不要只检查首行。
18. **检查**有期望值地址的 **「核对」** 结论。
19. **点击**需要核实的结果单元格，打开 **「点位结果」** 查看完整内容。
20. **核对**详情中的地址、类型、时间、标准化名称、期望值和点表行号，确认结果对应预期属性。

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| **「地址」** | 本次读取地址 | `DB1.R0` |
| **「名称」** | 从点表读取的属性名称；手动地址可以为空 | `一次供温` |
| **「类型」** | 实际读取和解码的数据类型 | `REAL` |
| **「值」** | 成功读取后的值；点表有单位时附带单位 | `85 ℃` |
| **「核对」** | 与点表期望值的比较结果；无期望值时为空 | **「一致」** |
| **「质量」** | `GOOD` 表示已取得有效结果；`BAD` 表示该项失败；`UNKNOWN` 表示该项结果未能确定 | `GOOD` |
| **「时间」** | 工具产生该项读取结果的本地时间 | `15:20:30.123` |
| **「错误」** | 服务拒绝、超时、解析等问题的具体信息 | 以实际返回为准 |

表中的时间用于定位工具侧读取记录，不等于 PLC 变量在程序内部最后更新的时间。

## 7 导入 viSCADA 点表并核对

### 7.1 准备 CSV 或 XLSX 文件

1. **取得** viSCADA 导出的物模型 `.xlsx` 文件，或整理为 `.csv` 文件。
2. **检查**地址列表头为 **「属性标识」**、**「地址」** 或 `address` 等受支持名称。
3. **检查**表头位于工作表前 `20` 行内。
4. **保留** **「属性名称」**、**「标准化名称」**、**「单位」** 等可读信息，便于现场对照。
5. **填写** **「期望值」** 或 **「模拟值」**，用于需要进行数值核对的属性。
6. **检查**文件大小不超过 `16` MB，单张表有效地址不超过 `1024` 个。
7. **保存** CSV 为 UTF-8 或 GBK/GB18030 编码，或者保留原始 XLSX。

| 字段 | 是否必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| **「属性标识」** / **「地址」** | 是 | `DB1.R0` | 优先使用自带类型的 viSCADA 标识 |
| **「属性名称」** | 否 | `一次供温` | 显示在结果表 **「名称」** 列 |
| **「标准化名称」** | 否 | `m_001t` | 用于详情中的业务对应，不改变 PLC 地址 |
| **「单位」** | 否 | `℃` | 只用于结果展示，不执行单位换算 |
| **「S7类型」** / **「类型」** | 否 | `REAL` | 原生非位地址需要此列；自带类型的标识可省略 |
| **「期望值」** / **「模拟值」** | 否 | `85.0` | 非空时核对；为空时只读取 |

XLSX 优先读取 **「设备类属性信息」** 工作表；程序选择包含有效地址表头的工作表，不会把整个工作簿所有 Sheet 合并。需要核对多张表时，分别整理后导入。两个期望值表头同时存在时，优先使用 **「期望值」** 列，建议仅保留一种，避免误读。

viSCADA 的 **「数据类型」** 数字编码，例如 `1`、`3`、`6`，不作为 S7 读写类型。`DB1.DBD0` 等原生地址应额外给出 `REAL`、`DINT` 等真实 S7 类型；`DB1.R0` 等标识能够直接确定类型。

可复制的 CSV 示例：

```csv
属性标识,属性名称,标准化名称,单位,期望值
DB1.R0,一次供温,m_001t,℃,85.0
DB1.R12,一次供压,m_001p,MPa,0.60
DB1.X52.0,通信状态,,,true
DB1.S60.16,故障信息,,,OK
```

原生地址需要类型列的示例：

```csv
地址,属性名称,类型,期望值
DB1.DBD0,一次供温,REAL,85.0
DB1.DBW4,运行计数,INT,12
DB1.DBX52.0,通信状态,BOOL,true
```

**「模拟值」** 在工具中作为比较基准使用，导入文件不会把这些值写入 PLC。现场动态数据应使用同一核对时段的有效基准；示例文件中的固定值不能直接作为任意生产设备的合格标准。

### 7.2 导入并处理跳过行

8. **停止**正在运行的轮询。
9. **点击** **「导入点表…」**。
10. **选择**准备好的 `.xlsx` 或 `.csv` 文件。
11. **点击**文件选择框中的 **「导入」**。
12. **查看**结果区上方的点表文件名、工作表名、导入数量和跳过数量。
13. **查看** **「部分行未导入」** 提示中的行号与原因，记录需要修改的行。
14. **修正**源文件中的无效地址、重复地址、缺少类型或无效期望值。
15. **重新导入**修正后的文件，确认有效地址数与计划核对数量一致。

导入会用点表中的全部有效地址替换当前地址框，并将数量设为 `1`，每个点使用自身类型。地址为空的行不参与读取；无效行被跳过时，不能把“文件导入成功”视为“文件内所有属性均已纳入”。超过 `1024` 个有效地址时，应拆成多个文件分别操作。

### 7.3 读取、判断与复制结果

16. **确认**当前连接目标为需要核对的 PLC。
17. **点击** **「读取一次」**，按导入顺序逐个读取地址；每完成一个地址，结果表立即增加该点的值、质量和核对结论。
18. **查看**点表汇总中的 **「逐点读取中 N/总数」** 或 **「已逐点读取 N/总数」**，同时检查 **「一致」**、**「不一致」**、**「读取失败」** 等计数。
19. **点击**异常行，查看 **「点位结果」** 中的源文件行号与期望值。
20. **核对**异常地址在 PLC 工程中的类型、偏移及当前值。
21. **点击** **「复制结果」**。
22. **粘贴**到 Excel 或其他支持制表符分列的工具，确认地址、名称、类型、值、核对、质量、时间和错误分别落列。
23. **补充**测试目标、设备名称、软件版本和测试时间后保存核对结果。

导入点表后的 **「读取一次」** 每次只向 PLC 请求一个地址。某个地址被 PLC 拒绝时，该点显示 `BAD`，工具继续读取下一点；连接中断或超时时停止本轮，保留已完成结果，尚未发出的点标记为 `UNKNOWN`，错误说明以“未读取”开头，时间显示为 `—`。需要主动中止时点击 **「断开」**；工具保留界面中已显示的结果，后续结果不再发布。恢复连接后可重新执行整轮验证。逐点读取期间不能更换或清除点表。手动地址读取和连续轮询仍采用原有的批量读取方式。

| 核对显示 | 含义 | 处理方法 |
| --- | --- | --- |
| **「一致」** | 读数与期望值按同一 S7 类型编码后相同 | 记录该项通过 |
| **「不一致」** | 本次读数有效，但与期望值不同 | 核对时刻、地址、类型及期望值来源 |
| **「读取失败」** | 该项没有取得可用于比较的有效读数 | 优先检查质量与错误信息 |
| 空白 | 未提供期望值，且本次读取成功 | 能证明读取成功，不能证明通过期望值核对；读取失败即使无期望值也显示 **「读取失败」** |

REAL 按 `32` 位精度显示和比较。例如期望值 `0.60` 与 PLC 中 REAL 的 `0.6` 可判定一致；其他系统将同一数值显示为 `0.6000000238418579` 属于浮点表示差异。本工具不配置工程容差区间，也不会自动进行比例缩放或单位换算。

24. **点击** **「清除点表」**，结束当前点表元数据与期望值核对。
25. **检查**地址框，按下一项任务重新填写需要读取的地址。

**「清除点表」** 清除的是名称、单位和期望值等关联信息，不会自动清空地址框，也不会清除 PLC 数据。

## 8 连续轮询与观察变化

1. **确认**一次读取已成功，当前地址范围和类型正确。
2. **填写** **「间隔（ms）」**，例如 `1000`。
3. **点击** **「开始轮询」**。
4. **查看**顶部 **「轮询中」** 标识。
5. **观察**结果表的值、时间、质量和核对结论随新一轮读取更新。
6. **点击** **「停止轮询」**，停止后续轮次。
7. **修改**地址、类型、数量或间隔后，重新点击 **「开始轮询」**。
8. **确认**新的读取结果对应修改后的地址和间隔。

轮询间隔最小为 `100` 毫秒，默认 `1000` 毫秒。工具在一轮读取完成后等待指定间隔再进行下一轮，实际刷新周期还包含通信耗时。轮询使用启动时的地址集合；修改输入后，应先停止再重新启动。

点击 **「停止轮询」** 后，已经发出的本轮读取仍可能完成。通信失败导致会话失效时，需要核对故障并手动重新连接，再启动轮询。

## 9 写入、确认与独立读回

### 9.1 准备单次写入

> ⚠️ 写入会修改目标 PLC 数据，可能影响阀门、泵或其他现场设备。仅对已明确允许修改的测试地址操作，先确认设备、工程含义、允许范围和现场状态。

1. **停止**正在运行的轮询。
2. **确认**顶部连接目标为本次允许操作的设备。
3. **填写** **「地址」** 为一个写入目标，不能保留多个逗号分隔地址。
4. **选择**与目标工程一致的 **「类型」**；带类型标识以其自身类型为准。
5. **填写** **「数量」**，单值为 `1`，连续数值数组填写实际元素数。
6. **填写** **「写入值」**，格式参考下表。
7. **勾选** **「允许写入（操作前仍需确认）」**。
8. **点击** **「确认写入…」**，或在写入值框按回车打开确认框。

| 类型 | 示例值 | 填写说明 |
| --- | --- | --- |
| `BOOL` | `true` / `false` | 一次一个位，数量为 `1` |
| `INT` / `DINT` / `LINT` 等整数 | `123` | 填写类型允许范围内的整数 |
| `REAL` / `LREAL` | `12.5` | 使用英文小数点 |
| 数值数组 | `1,2,3` | 使用英文逗号，元素数必须与数量一致 |
| `RAW` | `AA,00,FF` | 每项为一个十六进制字节，与指定字节数量匹配 |
| `DB1.C0` 对应的 `CHAR` | `A` | 单个可编码为 Windows-1252 的字符 |
| `DB1.S60.16` 对应的 `STRING[16]` | `OK` | 填字符串内容，不额外添加包裹引号；容量以地址或类型声明为准 |

字符串最大容量须在 `1～254` 字节内，另有两个头字节，数量必须为 `1`。需要 GUI 下拉框未列出的容量时，可使用 `DB1.S60.16` 这类自带最大长度的地址。

### 9.2 核对确认框并执行

9. **核对** **「确认 PLC 写入」** 弹窗中的目标地址与端口。
10. **核对**弹窗中的写入地址、类型、数量及写入值。
11. **点击**弹窗中的 **「确认写入」**。
12. **等待**写入结果与独立读回结果出现。
13. **核对**写入状态及读回结论，不要仅凭弹窗关闭判断成功。
14. **取消勾选** **「允许写入（操作前仍需确认）」**，结束当前写入权限。

| 写入状态 | 含义 | 后续处理 |
| --- | --- | --- |
| `CONFIRMED` | 收到该写操作的确认回应 | GUI 继续单独读取目标，检查读回是否一致 |
| `REJECTED` | 请求未提交或被拒绝 | 查看错误，核对权限、地址、类型和值 |
| `UNKNOWN` | 无法确定最终是否已写入 | 先恢复连接并读取当前值，结合现场状态决定后续操作 |

GUI 只在 `CONFIRMED` 后执行独立读回。**「一致」** 表示读回与写入值编码相同；**「不一致」** 表示读回有效但不同；**「无法确认」** 表示未取得有效读回。PLC 程序可能立即覆盖写入数据，因此读回不一致时还要核对程序逻辑。

> ⚠️ `UNKNOWN` 可能出现于 PLC 已完成写入、但确认回应丢失的情形。工具不会自动重发写入，应先读取和核实现场状态，避免重复动作。

### 9.3 处理写入后的核实

15. **恢复**因超时或断线失效的连接。
16. **点击** **「读取一次」**，核实目标当前值。
17. **查看** **「报文」** 页签中的写请求、回应及后续读取。
18. **记录**最终读数、时间、写入状态及现场确认结果。

一次 GUI 写入只允许一个起始地址，数值数组可以从该地址连续写入。大数据分段写入没有事务原子性，可能出现部分段已生效、后续段失败；跨多批读取也不提供原子快照。

## 10 查看报文、日志与本地记录

### 10.1 查看并复制通信报文

1. **切换** **「报文」** 页签。
2. **选择**与问题时间接近的一条收发记录。
3. **查看**详情中的时间、方向、操作、请求 ID、PDU 引用、状态、错误和连接标识。
4. **查看** **「真实报文字节」**，确认实际收到或发出的十六进制数据。
5. **点击** **「复制详情」**，保存该条完整报文信息。
6. **选择**同一操作相邻的请求和回应，分别复制，形成可对应的取证材料。

`TX` 表示工具发向 PLC 的数据，`RX` 表示工具从 PLC 收到的数据。界面保留最近 `256` 条报文，持续通信后较早记录会退出界面列表；本地记录器用于保留更完整的握手与收发事件。请求 ID 和 PDU 引用用于关联通信，不是 PLC 地址。

### 10.2 查看日志与定位记录文件

7. **切换** **「日志」** 页签。
8. **查看**连接、读取、写入或退出相关状态，定位问题发生顺序。
9. **点击** **「复制日志」**，保存当前显示的日志文本。
10. **点击**窗口底部 **「打开记录目录」**。
11. **确认**记录目录能够打开，底部没有 **「记录失败」** 提示。
12. **正常关闭**程序，等待本地记录队列排空后再复制本次数据库文件。

| 记录位置 | 内容 | 使用说明 |
| --- | --- | --- |
| `%AppData%\S7AIStudio\records` | SQLite 通信记录 | GUI 默认目录，按天及单文件约 `50` MB 轮转 |
| `%AppData%\S7AIStudio\app.log` | 应用运行日志 | 启动、退出等应用问题可结合此文件定位 |
| **「报文」** 页签 | 最近 `256` 条真实收发 | 用于快速查看与复制单条详情 |
| **「日志」** 页签 | 最近 `100` 条状态文本 | 用于快速查看操作顺序 |

正常关闭会排空记录队列并释放本机演示端口。出现本地保存失败时，通信成功不代表取证记录已完整落盘，应及时复制可见结果、报文与日志，再检查目录权限和磁盘空间。

## 11 结束调试与保存交付材料

1. **点击** **「停止轮询」**。
2. **取消勾选** **「允许写入（操作前仍需确认）」**。
3. **点击** **「复制结果」**，保存最终读取或核对表。
4. **点击** **「复制日志」**，保存需要交接的状态信息。
5. **复制**异常请求和回应的报文详情。
6. **点击** **「断开」**；使用本机演示时点击 **「停止演示」**。
7. **关闭**程序，等待退出完成。
8. **保存**本次点表、核对结果、记录数据库和必要的应用日志。
9. **记录** PLC 型号、固件、目标地址、Rack/Slot 或 TSAP、软件版本、测试时间和验证范围。
10. **确认**交付材料能区分本机模拟验证与真实 PLC 验证，能区分只读通过与写入及读回通过。

工具读取成功只验证所选地址和当时通信链路。viSCADA 后续采集、标准化映射和配置生效仍需回到平台验证，参阅 [viSCADA S7 数据对接配置手册](http://mrdoc.iheatingos.com/project-36/doc-13621/)。

## 12 常见问题与排查

| 现象 | 可能原因 | 处理建议 |
| --- | --- | --- |
| 程序无法启动、图形窗口异常或空白 | 系统架构不符、图形驱动不支持 OpenGL、文件未完整解压 | 核对 Windows x64、更新适用显卡驱动、重新完整解压，查看 `app.log` |
| 提示目标必须为 `host:port` | 只填 IP，或输入了 `http://` 前缀 | 填写 `192.168.0.10:102` 形式的实际目标 |
| TCP 连接超时或拒绝连接 | IP/端口错误、路由或防火墙限制、目标服务未开放 | 核对现场参数和网络策略；端口通后继续检查协议握手 |
| 网络可达但 S7 握手失败 | TSAP、Rack/Slot 错误，目标不是经典 S7 服务，连接资源不足 | 核对工程配置和服务类型，复制握手阶段报文 |
| 提示必须填写 Remote TSAP | 所选系列要求显式远端连接参数 | 向 PLC 或网关维护人员取得 Remote TSAP 后填写 |
| 已连接，但所有 DB 地址读取失败 | 访问许可不足、PUT/GET 未允许、DB 优化访问或 DB 不存在 | 由 PLC 工程维护人员核对[第 4.3 节](#4.3%20%E6%A0%B8%E5%AF%B9%20S7-1200%2F1500%20%E7%9A%84%E7%BB%9D%E5%AF%B9%E5%9C%B0%E5%9D%80%E8%AE%BF%E9%97%AE)各项，先读一个已知地址 |
| 只有部分地址失败 | DB 编号、偏移、位号或 DB 长度不符 | 根据失败行逐项核对，不要用其他 `GOOD` 行替代该项验收 |
| 读数有效但明显不符合业务含义 | REAL/整数类型选错，偏移不符，单位或比例理解错误 | 与工程变量类型核对；工具不会自动换算工程比例或单位 |
| 提示位地址或数量不合法 | BOOL 缺少位号、位号超过 `7`、BOOL/STRING 数量大于 `1` | 使用完整位地址，数量改为 `1`；多个 BOOL 用多个地址 |
| PE、PA、MK 地址无法导入 | 区域编号不是 `0` 或格式错误 | 使用 `PE0.X0.1`、`PA0.B2`、`MK0.R4` 等格式 |
| DT、计数器、定时器行被跳过 | 当前版本未解析对应类型或区域 | 从当前核对表剔出，单独采用支持该对象的方式核实 |
| 提示 V 地址需要映射 | 未配置 V/VM 到 DB 的关系 | 根据设备或网关映射填写 DB 和偏移，不直接假设 DB1 |
| XLSX 提示找不到地址列 | 工作表没有受支持表头，或表头不在前 `20` 行 | 整理为单表，保留 **「属性标识」** 或 **「地址」** 等表头 |
| 文件导入成功，但数量少于预期 | 空地址行、无效地址、重复地址、类型缺失或期望值无效 | 查看跳过行提示，按源文件行号修正后重新导入 |
| 原生地址提示缺少 S7 类型 | 表里只有平台数字类型编码 | 增加 **「S7类型」** 列填写 `REAL` 等，或改为带类型标识 |
| 提示文件被 E-SafeNet 透明加密 | 程序读取到密文 | 使用浏览器从 viSCADA 下载的原始文件；必要时联系管理员为程序配置授权 |
| 点表没有 **「核对」** 结论 | 没有期望值，或已清除点表元数据 | 检查 **「期望值」** / **「模拟值」** 列后重新导入 |
| REAL 与其他系统显示的小数位不同 | 同一浮点值采用不同显示精度 | 按同一 S7 类型比较，核对原始值，不只比较字符串小数位 |
| CHAR/STRING 乱码或中文写入被拒绝 | 代码页与 Windows-1252 不一致，或字符不可编码 | 核对 PLC 字符编码；从报文页查看原始字节 |
| 写入按钮不可用 | 未连接、后台忙、未勾选允许写入等 | 等操作结束，核对连接与允许写入状态后重新打开确认框 |
| 提示每次写入只能指定一个地址 | 地址框仍保留导入后的多个地址 | 只保留本次允许写入的一个起始地址 |
| 写入为 `CONFIRMED`，读回却不一致 | PLC 程序覆盖、写入目标或数据布局不符 | 核对程序逻辑和目标地址，保留写请求与读回报文 |
| 写入为 `UNKNOWN` | 断线、超时或写回应丢失 | 重新连接后先读取当前值，结合现场状态核实，避免直接重复写入 |
| 轮询停止或通信失败后不能继续读取 | 传输异常使会话失效 | 核对网络和错误详情，手动重新连接后再开始轮询 |
| 修改地址后轮询仍读取旧地址 | 当前轮询使用启动时的地址集合 | 停止轮询后重新启动 |
| 停止轮询后又出现一次更新 | 已发出的本轮读取完成 | 等待本轮结束；结束会话时使用断开 |
| 底部提示记录失败 | 目录权限、磁盘空间或数据库保存异常 | 先复制可见结果和日志，再检查记录目录与磁盘，正常退出保存剩余记录 |
| 选择系列后仍不能连接某型号 | 档案不代表已完成实机兼容验证 | 提供型号、固件、通信模块、接入路径及握手报文进一步核实 |

更完整的设备与平台链路排查参阅 [viSCADA S7 协议常见问题排查](http://mrdoc.iheatingos.com/project-36/doc-13101/)。

## 14 附录：命令行与独立模拟器

本附录用于已有 `s7-cli`、`s7-sim` 可执行文件的调试环境。GUI 绿色包的使用不依赖命令行工具；不要假定 GUI ZIP 必然附带这两个文件。需要自行构建时，使用项目源码 `go.mod` 指定的 Go 工具链。

### 14.1 构建与读取

1. **打开**项目源码根目录的 PowerShell。
2. **执行**以下命令生成两个工具。

```powershell
go build -o bin/s7-cli.exe ./cmd/s7-cli
go build -o bin/s7-sim.exe ./cmd/s7-sim
```

3. **执行**读取命令，将示例目标替换为实际参数。

```powershell
.\bin\s7-cli.exe -target 192.168.0.10:102 -family s7-1200 -type REAL read DB1.DBD0
.\bin\s7-cli.exe -target 192.168.0.10:102 -family s7-1200 read DB1.R0,DB1.X52.0
.\bin\s7-cli.exe -target 192.168.0.10:102 -family s7-1200 -json read DB1.R0
```

4. **检查**命令输出和退出码，确认各项质量与数值符合预期。

所有选项必须放在 `read`、`write`、`verify` 前。CLI 默认原生地址类型为 `INT`，不同于 GUI 默认的 `DINT`，读取原生地址时建议显式指定 `-type`。带类型标识可省略 `-type`；显式指定时需与标识类型一致。

### 14.2 运行点表模拟与核对

5. **在第一个终端执行**以下命令，让模拟器按项目示例点表预置数据。

```powershell
.\bin\s7-sim.exe -listen 127.0.0.1:1102 -points assets\examples\viscada-heat-station-s7.csv
```

6. **在第二个终端执行**点表核对。

```powershell
.\bin\s7-cli.exe -target 127.0.0.1:1102 -points assets\examples\viscada-heat-station-s7.csv verify
.\bin\s7-cli.exe -target 127.0.0.1:1102 -points assets\examples\viscada-heat-station-s7.csv -json verify
```

7. **检查**示例中的 `47` 个地址，即 `39` 个 REAL 和 `8` 个 BOOL 的读取与核对结果。
8. **在模拟器终端按** `Ctrl+C`，结束监听。

`verify` 按点表顺序逐个地址发送读取请求，结束后统一输出文本或 JSON 报告；CLI 输出不随每个点实时刷新。单点服务拒绝后继续，通信中断时停止并保留已取得结果。全部读到且没有不一致时退出码为 `0`，通信或核对失败为 `1`，参数错误为 `2`。没有期望值的地址只读取，不能据此声明每个属性均已完成期望值核对。GUI 内置本机演示只提供其默认演示数据；独立模拟器的 `-points` 才按整张点表预置数值。

### 14.3 命令行写入与记录

9. **仅在本机模拟环境中执行**以下写入示例；模拟器需已监听该端口。

```powershell
.\bin\s7-cli.exe -target 127.0.0.1:1102 -type DINT -allow-write write DB1.DBD0 123
.\bin\s7-cli.exe -target 127.0.0.1:1102 -type DINT read DB1.DBD0
```

10. **执行**带记录目录的读取命令，保存通信事件。

```powershell
.\bin\s7-cli.exe -target 127.0.0.1:1102 -type DINT -record '.\通信历史' read DB1.DBD0
```

11. **检查**写入状态、独立读取结果及记录文件，确认命令按预期完成。

CLI 的 `write` 返回 `CONFIRMED` 表示收到确认回应，不自动执行 GUI 中的独立读回流程，需另发 `read` 命令核实。`-record` 使用显式指定的目录；JSON 整数使用十进制字符串保存完整精度。

地址规则的上游说明见 [Telegraf inputs.s7comm 文档](https://github.com/influxdata/telegraf/blob/master/plugins/inputs/s7comm/README.md)。本工具只支持本手册明确列出的地址与类型，不能把上游插件全部能力视为当前工具已实现的功能。
