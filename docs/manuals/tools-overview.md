**按问题快速定位：**

- 需要验证 MQTT 消息是否发出、收到：进入 `1601`。
- 需要 IEC104 主站模拟工具：进入 `1602`。
- 需要直接发送或查看串口、网络原始报文：进入 `1603`。
- 需要调试 Modbus 寄存器或点表：进入 `1604`。
- 需要批量检查平台能否到达设备 IP 和端口：进入 `1605`。
- 需要读取西门子 PLC 或核对 S7 物模型属性：进入 `1606`。

## 3 排查顺序与结果边界

### 3.1 网络设备无法通信

1. **确认**设备 IP、端口及测试发起位置。
2. **使用**对应网络测试功能检查目标是否可达。
3. **进入**对应协议工具，核对连接参数和握手结果。
4. **读取**一个地址明确、类型明确且数值已知的属性或寄存器。
5. **扩大**到整张点表，检查失败项与数值不一致项。
6. **回到** viSCADA 检查平台采集、属性映射及后续数据处理结果。

网络测试工具的 Ping、TCP 测试由平台诊断节点发起，反映平台到设备的网络；本机桌面协议工具反映调试电脑到设备的链路。两者测试位置不同，结果需要结合网络拓扑判断。

### 3.2 正确理解测试通过

| 已观察到的结果 | 可以确认的内容 | 仍需继续验证的内容 |
| --- | --- | --- |
| Ping 有回应 | 测试发起位置到目标的 ICMP 通信可达 | TCP 端口、协议服务及数据访问 |
| TCP 端口连接成功 | 目标 IP 和端口能够建立 TCP 连接 | 协议握手、访问许可及地址正确性 |
| 协议连接成功 | 当前参数能够完成对应连接流程 | 具体属性或寄存器能否读取、解码是否正确 |
| 取得有效读数 | 当前地址读取成功 | 类型、单位、缩放和业务含义是否与工程一致 |
| 点表数值核对一致 | 本次有效读数与给定期望值符合工具的比较规则 | 动态工况下的持续表现、未纳入或未提供期望值的属性 |
| 本机演示通过 | 工具的模拟通信流程能够运行 | 真实设备型号、固件、访问设置及现场网络 |

S7 AI Studio 的型号档案用于提供连接参数起点，不能替代具体型号与固件的实机验证。各工具的支持协议、地址格式和功能范围，以对应版本手册为准。

## 4 测试记录与交接

1. **记录**工具名称和版本、测试时间、设备名称、型号及固件。
2. **记录**实际目标、协议参数和测试发起位置。
3. **保存**原始点表、读取结果、异常提示及关键收发报文。
4. **标明**哪些项目属于模拟验证、实机读取、数值核对或写入及读回验证。
5. **停止**轮询或持续发送，结束当前连接。
6. **正常退出**工具，按对应手册完成记录文件保存。

> ⚠️ 写入或发送控制类消息前，须核对目标设备、地址、内容及现场允许范围。出现写入结果不确定时，先核实设备当前状态，再决定后续操作。

本页维护工具选择与手册入口。某个工具的下载版本、参数或操作步骤发生变化时，应更新其子文档；新增工具时再补充本页目录。
